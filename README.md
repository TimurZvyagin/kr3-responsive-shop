# kr3-responsive-shop — Винтаж-лавка

## Контрольная работа №3

Тема: «Адаптивная вёрстка и доступность многостраничного HTML/CSS-сайта».

## Описание проекта

Интернет-магазин винтажных вещей «Винтаж-лавка». За основу взят HTML/CSS-проект из КР №1 ([kr1-html-shop](https://github.com/TimurZvyagin/kr1-html-shop)), его история коммитов сохранена в этом репозитории. Bootstrap и другие CSS-фреймворки не используются: сетки, медиазапросы и компоненты написаны вручную.

В КР №3 сайт адаптирован под экраны от 320 до 1440 px и проверен на доступность. Каталог расширен до 8 товаров, у каждого товара есть своя страница.

## Подключение стилей

На каждой странице:

```html
<meta name="viewport" content="width=device-width, initial-scale=1.0" />
<link rel="stylesheet" href="css/style.css" />
<link rel="stylesheet" href="css/responsive.css" />
```

`responsive.css` подключается после `style.css`, чтобы медиазапросы переопределяли базовые правила.

## Адаптивные решения

**Подход Mobile First.** `style.css` описывает телефон: одна колонка, кнопки во всю ширину, свёрнутые меню и фильтр. В `responsive.css` раскладка расширяется через `min-width` по шагам. Единственное исключение — `max-width: 599.98px` для карточного вида таблицы сравнения: его проще описать только для узкого экрана, чем отменять на всех остальных ширинах.

| Ширина  | Что меняется                                                                                   |
| ------- | ---------------------------------------------------------------------------------------------- |
| базовая | одна колонка, меню под кнопкой «Меню», фильтр свёрнут, таблица сравнения в виде карточек      |
| ≥ 480   | карточки в 2 колонки, кнопки в строку, контакты в 2 колонки, окно заявки по центру            |
| ≥ 768   | меню в строку, hero в 2 колонки, преимущества в 3 колонки, фильтр слева, форма в 2 колонки, подвал в 3 колонки |
| ≥ 1024  | каталог в 3 колонки, популярные товары в 4, контакты в 4 колонки, форма обратной связи рядом с описанием |
| ≥ 1440  | контейнер 1240 px, каталог в 4 колонки                                                         |

**Навигация.** На телефоне ссылки спрятаны под кнопкой «Меню» со значком ☰, который меняется на ✕. Кнопка сообщает состояние через `aria-expanded`. Меню закрывается по Esc (фокус возвращается на кнопку), по клику мимо, после выбора пункта и при переходе на широкий экран. Без JavaScript кнопка не показывается, а меню выводится обычным списком. С 768 px ссылки стоят в строку, активный пункт подчёркнут.

**Hero-блок.** На телефоне текст по центру, кнопки друг под другом, под ними квадратное фото. С 768 px текст и фото в две колонки (Grid), а фото меняется на широкий кадр (art direction через `<picture>`). Размер заголовка плавно меняется через `clamp()`.

**Сетка карточек (CSS Grid).** 1 → 2 → 3 → 4 колонки в зависимости от ширины. Фото карточек всегда в пропорции 4:3 (`aspect-ratio` + `object-fit`).

**Каталог и фильтр.** На телефоне фильтр свёрнут в `<details>` под заголовком «Фильтры». С 768 px он становится боковой колонкой, всегда раскрыт и прилипает при прокрутке (`position: sticky`). Фильтрация работает **на чистом CSS** через селектор `:has()`. Категории объединяются по «ИЛИ», метки «Только хиты» и «Со скидкой» — по «И». JavaScript только считает найденные товары и показывает сообщение, если ничего не нашлось.

**Страница товара.** На телефоне фото над описанием, с 768 px — рядом (Grid). Кнопки действий на Flexbox: в столбик на телефоне, в строку с 480 px.

**Таблицы.**
- «Характеристики» обёрнута в `.table-wrapper` с `overflow-x: auto`.
- «Сравнение с похожими» на телефоне показывается **карточками**: каждая характеристика — отдельная карточка, а название товара подставляется из `data-label` через `::before`. От 600 px это обычная таблица внутри `.table-wrapper` с `min-width: 560px`, она прокручивается внутри обёртки, а не вся страница.

**Формы.** На телефоне одна колонка, с 768 px пары полей (имя + e-mail, телефон + товар) встают в две колонки. Поля высотой 44 px и шрифтом 16 px: мобильный Safari не увеличивает страницу при фокусе. Используются `type="email"`, `type="tel"`, `inputmode` и `autocomplete`, поэтому на телефоне открывается нужная клавиатура. Кнопки разделены отступом (`gap`), на телефоне идут в столбик.

**Модальное окно.** Сделано на `<dialog>`. На телефоне выезжает снизу на всю ширину («шторка»), с 480 px — по центру экрана.

**Подвал.** На телефоне блоки друг под другом по центру, с 768 px — три колонки.

**Без горизонтального скролла.** `overflow-wrap: break-word` для длинных слов, `max-width: 100%` для изображений, `min-width: 0` у полей формы. Широкая таблица прокручивается только внутри `.table-wrapper`.

## Responsive images

- Общее правило в `style.css`:
  ```css
  img,
  video {
    max-width: 100%;
    height: auto;
  }
  ```
- **`srcset` + `sizes`** — у всех фото товаров есть версии 320, 480 и 640 px. `sizes` описывает ширину картинки в сетке на каждой ширине экрана, и браузер сам выбирает подходящий файл.
- **Формат WebP через `<picture>`**, JPEG — запасной вариант для старых браузеров. Три размера фото камеры весят 37 КБ в WebP против 75 КБ в JPEG при том же качестве.
- **Art direction** — в hero на телефоне показывается квадратный кадр крупным планом, с 768 px — широкий кадр полки (`<source media="(min-width: 768px)">`).
- Атрибуты `width` и `height` у всех изображений: страница не прыгает при загрузке.
- `loading="lazy"` для фото ниже первого экрана, `fetchpriority="high"` для главного фото.

## Доступность

Что исправлено и добавлено по сравнению с КР №1:

- **Ссылка пропуска** «Перейти к основному содержимому» появляется первой при нажатии Tab и ведёт на `<main id="main">`.
- **Видимый фокус** на всех интерактивных элементах через `:focus-visible`: тёмно-синяя рамка на светлом фоне, белая — в шапке и подвале.
- **Один `h1` на странице, заголовки по порядку.** В каталоге добавлен скрытый `h2` «Товары» перед карточками с `h3`.
- **Навигация** размечена `<nav>` с `aria-label` (основное меню, разделы главной, хлебные крошки, подвал), у активной ссылки `aria-current="page"`.
- **Формы:** у каждого поля есть `<label>`. Обязательные поля помечены `required` и звёздочкой; звёздочка скрыта от экранных дикторов, потому что они и так сообщают «обязательное». Подсказки связаны с полями через `aria-describedby`. Радиокнопки сгруппированы в `<fieldset>` с `<legend>`. Ошибки подсвечиваются через `:user-invalid` — только после того, как пользователь заполнял поле.
- **Изображения:** у всех фото товаров осмысленный `alt`.
- **Ссылки «Подробнее»** дополнены скрытым текстом «о товаре „…“», чтобы в списке ссылок было понятно, куда ведёт каждая.
- **Контраст:** вторичный текст сделан темнее (`#4b5563`, контраст 7,5:1), бейджи «Новинка» и «Скидка» — белый текст на тёмном фоне (контраст от 5:1).
- **Модальное окно на `<dialog>`:** фокус переходит в окно и не уходит за его пределы, Esc закрывает окно, после закрытия фокус возвращается на кнопку «Быстрая заявка». Без JavaScript кнопка просто ведёт на `order.html`.
- **Мобильное меню:** `aria-expanded` и `aria-controls`, закрытие по Esc.
- **ARIA только где нужно:** `aria-expanded` у меню, `aria-current`, `aria-live` у счётчика каталога. Роли `table`/`row`/`cell` у таблицы сравнения нужны, чтобы экранные дикторы читали её как таблицу, когда на телефоне строки превращаются в карточки.
- Области нажатия не меньше 44×44 px.

## Lighthouse

Проверка Lighthouse 12.8 (категория Accessibility, мобильный режим):

| Страница        | Accessibility |
| --------------- | ------------- |
| `index.html`    | 100           |
| `catalog.html`  | 100           |
| `product.html`  | 100           |
| `order.html`    | 100           |
| `contacts.html` | 100           |

Отчёты лежат в папке `lighthouse/`:

- `accessibility-report.png` — скриншот отчёта главной страницы;
- `catalog-accessibility.png`, `order-accessibility.png` — скриншоты отчётов каталога и заявки;
- `*-accessibility.html` — полные отчёты по всем пяти страницам, открываются в браузере.

Lighthouse находит только то, что можно проверить автоматически. Поэтому вручную проверены переходы по Tab, работа окна и меню с клавиатуры, порядок заголовков и подписи полей.

## Проверенные ширины

Все страницы проверены на ширинах **320, 360, 430, 768, 1024 и 1440 px** (DevTools → режим устройства). Проверены шапка, меню, hero, сетка карточек, каталог и фильтр, страница товара, обе таблицы, формы, контакты, подвал и окно заявки. Горизонтального скролла страницы нет ни на одной ширине.

Скриншоты — в папке `screenshots/`: главная на 360, 768 и 1440 px, каталог на 360 и 1024 px, форма заявки на 360 px.

## Самостоятельные доработки

1. **Мобильное меню** с кнопкой ☰/✕, `aria-expanded`, закрытием по Esc, по клику мимо и после выбора пункта. Без JavaScript работает как обычный список.
2. **Фильтр каталога на чистом CSS** через `:has()`: категории по «ИЛИ», метки по «И», сброс кнопкой. На телефоне фильтр свёрнут в `<details>`, на планшете и компьютере это боковая колонка с `position: sticky`.
3. **Карточный вид таблицы сравнения** на телефоне вместо горизонтальной прокрутки.
4. **Несколько вариантов responsive images:** `srcset`/`sizes` в трёх размерах, формат WebP с запасным JPEG через `<picture>` и разные кадры hero для телефона и компьютера.
5. **Доступное модальное окно** на `<dialog>`: на телефоне выезжает снизу, на широком экране стоит по центру.
6. **Расширенный каталог:** 8 товаров, у каждого своя страница с таблицей характеристик и сравнением с похожими; хлебные крошки на внутренних страницах.
7. **Улучшенные формы:** `:user-invalid`, подсказки через `aria-describedby`, `inputmode`/`autocomplete`, выбор способа связи.
8. **Lighthouse 100** по доступности на всех пяти основных страницах.

## Как проверить

1. Откройте сайт по ссылке GitHub Pages или файл `index.html`.
2. В DevTools включите режим устройства и пройдите ширины 360, 430, 768, 1024 и 1440 px.
3. На узком экране нажмите «Меню», затем Esc — меню закроется, фокус вернётся на кнопку.
4. В каталоге раскройте «Фильтры», отметьте «Инструменты» и «Только хиты» — останется один товар. Отметьте ещё «Со скидкой» — появится сообщение «ничего не нашлось».
5. Нажмите «Быстрая заявка», пройдите поля клавишей Tab, закройте окно по Esc.
6. На странице `product-tools.html` сравните таблицу сравнения на 360 и 768 px.
7. Нажмите Tab сразу после загрузки любой страницы — появится ссылка «Перейти к основному содержимому».
